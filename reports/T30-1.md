## T30 — CORE-7347 · [RF] 404 page missing styled content, needs header/footer confirmed

### 1. Summary
The clone's `not-found.tsx` rendered a bare Payload-scaffold placeholder ("404" / "This page could not be found." / "Go home" button) instead of Live's styled 404 page. Header/footer were already correct per the ticket (confirmed, no regression needed). Built a new `NotFoundContent` shared component that reproduces Live's content 1:1 (heading, subheading, paragraph copy, icon link, illustration) and wired it into `not-found.tsx` in place of the placeholder.

### 2. Root cause
`src/app/(frontend)/not-found.tsx` was the generic Payload website-template scaffold, never replaced with real 404 content when the site was ported from Live. It rendered `<Header />` correctly but the `<main>` body was the template's placeholder markup.

### 3. Fix
- Scraped Live's actual 404 HTML/CSS (`curl` against `rapidformations.co.uk/<nonexistent-path>`) to get exact copy, structure, and colours — no Figma design exists for this page, so Live is the only source of truth.
- New component: `src/components/shared/NotFoundContent/{NotFoundContent.tsx,NotFoundContent.styles.ts}` — styles+component pattern per CLAUDE.md, placed under `components/shared/` (page-level content, not a Payload block).
- Content: "Error 404" (h1, `--text-info` = exact `#3498db` match), "Page not available" (h2, `--text-on-light-muted` = exact `#595959` match), the full explanatory paragraph, a plain icon+text link ("Go back to homepage.") to `/` using lucide's `CircleChevronLeft` (exact equivalent of Live's FontAwesome `circle-chevron-left`), and the illustration image.
- Illustration downloaded from Live and added as a static asset at `public/images/errors/404-staff-illustration.png` (561×392, matches the existing `public/images/namecheck/*.png` static-asset convention already used in this codebase — not a CMS/Payload media upload, so it stays outside lane T6's media-asset boundary).
- `next/image` requires `unoptimized` for anything under `public/images/` because `next.config.ts`'s `images.localPatterns` only allow-lists `/api/media/file/**` — followed the existing precedent in `src/components/shared/NameCheck/index.tsx`.
- Typography/colour follow the codebase's established "on-light legacy content" convention (raw `text-[Npx]` + `--text-on-light-*` / `--text-info` vars, see `RequiredInformation.styles.ts`) rather than the modern responsive `Text` presets, because this content has no Figma source and Live's typography here is fixed-px, not responsive.
- Card background: initially used `--surface-primary`, which turned out to be a **dark navy** value specific to `.theme-rapidformations` (used elsewhere for intentionally-dark cards) — caught via screenshot, corrected to `--surface-canvas` (true white, verified via globals.css) to match Live.
- `not-found.tsx` simplified to `<Header /><main><NotFoundContent /></main></Header>` — `<Footer />` is already rendered by the root layout for every page (confirmed unrelated to this bug) so nothing further was needed there, matching the ticket's own confirmation.

### 4. Challenges / blockers
- **Turbopack build/dev failure specific to this worktree**: `bun run build` and `bun run dev` both failed immediately with `TurbopackInternalError: Symlink [project]/node_modules is invalid, it points out of the filesystem root`. Root-caused: `next.config.ts`'s `turbopack.root: path.resolve(dirname)` resolves to the worktree dir (`/Users/eugeniucozac/bsqgroup/rf-t30`), but this worktree's `node_modules` is a symlink to a **sibling** directory (`/Users/eugeniucozac/bsqgroup/rapid-formations-clone/node_modules`) outside that root — Turbopack rejects any package resolution that escapes the configured root. This is a structural property of how every `rf-*` lane worktree is bootstrapped (all use the same symlink pattern), so it will hit every lane that runs a fresh `build`/`dev` in one of these worktrees, not just this task.
  - Diagnosed by temporarily widening `turbopack.root` to the shared parent (`/Users/eugeniucozac/bsqgroup`) — confirmed this was the exact cause (build then proceeded past the symlink error). **Reverted before commit** — `git diff next.config.ts` is clean; nothing infra-related shipped in this PR.
  - Used the widened-root config **only** as a local, temporary, unshipped workaround to get `bun run dev` serving so the mandated Playwright screenshot verification could run. Filing a proposal (see §9) so this doesn't cost the next lane the same ~10 minutes.
- Caught two real bugs via the mandatory screenshot verification (not just code reading, per CLAUDE.md's Live App Verification rule): (a) `next/image` threw client-side because `/images/errors/...` isn't covered by `images.localPatterns` — fixed with `unoptimized` (existing precedent); (b) the card background using `--surface-primary` rendered as dark navy instead of white, because that token is brand-theme-dark for `.theme-rapidformations` — fixed by switching to `--surface-canvas`.

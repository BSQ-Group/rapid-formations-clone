# T20 — CORE-7322 · Compare-packages minus icon size/colour — Round 1

**1. Task:** T20 / CORE-7322 — `/compare-packages/` desktop comparison grid "not included" minus icon renders too small and too dark vs live.

**2. Status:** Fix implemented, committed, pushed, PR #228 opened. Awaiting user merge.

**3. What changed:** `src/blocks/ComparePackageTable/ComparePackageTable.styles.ts` — the `minus` style key changed from
`h-[15px] w-auto text-[var(--text-on-light-base)]` to `h-[1.25em] w-auto text-[var(--icon-on-light-faint)]`,
matching the sibling `check` key's sizing unit (`1.25em`, scales with the row's `text-[26px]`) and using the
existing `--icon-on-light-faint: rgb(199 199 199)` token (already used elsewhere in this same file for `infoIcon`)
instead of the text-color token `--text-on-light-base` it had been mistakenly given. One-line change, one file.
Root cause confirmed via a dedicated investigation subagent: both icons render through the same shared `FaIcon`
wrapper (`src/components/shared/FaIcon`), which applies zero default size/colour (only `shrink-0`) — all
sizing/colour is block-local in `ComparePackageTable.styles.ts`. Confirmed this is NOT a shared/engine-level
component used by other blocks (searched for other `faMinus`/`faCheck` usages — each consuming block defines its
own independent style key), so this stays a direct, local bug fix per the Mode X bug-lane exemption rather than
being kicked back as clone-fidelity/engine work.

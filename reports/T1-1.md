# T1-1 — CORE-7009 review star size fix

**What was wrong:** The clone's `Star` glyph (`src/components/shared/RatingStars/index.tsx`) used
`viewBox="0 0 25 24"` with a path whose coordinates filled almost the entire box, so the star drew
edge-to-edge inside its 25×25 CSS box. Live's star uses `viewBox="0 0 51 48"` with a path that leaves
proportionally more empty margin around the glyph — same box size, same fill colour, but a visibly
smaller/thinner star shape, which reads as "chunkier/darker" on the clone at any breakpoint (box size
was never the issue, per the ticket).

**What I changed:** One file, `src/components/shared/RatingStars/index.tsx` — swapped the `Star`
component's `viewBox` to `0 0 51 48` and replaced the `path d` with live's exact path, fetched
directly from `https://www.rapidformations.co.uk/faqs/`:

```html
<svg viewBox="0 0 51 48" ...><path d="m25,1 6,17h18l-14,11 5,17-15-10-15,10 5-17-14-11h18z"/></svg>
```

This is a byte-identical glyph match to live, not an approximation. Box sizing (`RatingStars.styles.ts`
`size.{xs..xl}`, all in px) and colour tokens (`starEmpty`, `tone.*`) were untouched — no other file
changed.

**How I verified it:**
- Fetched live's `/faqs/` HTML directly (curl) and confirmed all 10 star `<svg>` nodes share the same
  `viewBox="0 0 51 48"` + path `d` — used that as the source of truth per project convention (source
  of truth is the live site, not a screenshot approximation).
- `bun run ts` — clean, no type errors.
- `git diff --stat` — confirmed only `RatingStars/index.tsx` changed (2 lines), no stray files staged.
- **Could NOT verify with a live browser render** — see blocker below. This is the one gap the gate
  lane needs to close.
